# orchid — Agentic Orchestration Fingerprinting

> **Next-generation technical assessment for engineering leadership roles.**
> orchid evaluates how candidates think alongside AI — not what code they produce.

---

## The problem with existing technical interviews

Current technical assessments measure individual coding output in artificial isolation. They cannot answer the question that actually predicts performance in modern engineering teams:

> *How does this person lead, correct, and reason alongside AI agents under real operational pressure?*

A candidate who can write a flawless sorting algorithm may completely freeze when an AI hallucinate a column name, a Kafka pipeline silently dies, and a schema corruption hits simultaneously. The reverse is equally common.

---

## Value proposition

orchid replaces the whiteboard with a live operational incident.

- **For hiring teams**: receive a structured Algorithmic Leadership Profile — not a pass/fail score, but a five-dimension fingerprint of how the candidate orchestrates AI under pressure.
- **For candidates**: a realistic, relevant challenge that reflects actual on-the-job conditions.
- **For engineering leaders**: signal on the capabilities that matter most as AI co-pilots become standard — delegation quality, correction velocity, chaos resilience.

No LLM interview theater. No prompt-engineering tricks. Pure leadership signal.

---

## How it works

```
Candidate → Sandbox (VS Code) → Sub-agents (DELTA · NOVA · ECHO)
                ↓ telemetry stream (Kafka)
         Shadow Agent (Claude) observes, never intervenes
                ↓
       OrchestraFingerprint assembled (Airflow DAG)
                ↓
    Hiring team receives Cognitive Blueprint Dashboard
```

### The scenario

Each session presents a **live operational incident** — a corrupted data warehouse, a silent Kafka pipeline, a broken Airflow DAG. The candidate has 60 minutes to diagnose and resolve it by directing three AI sub-agents:

| Agent | Persona | Deliberate weakness |
|---|---|---|
| **DELTA** | Data Engineer | Occasionally hallucinates column names |
| **NOVA** | Pipeline Debugger | Overly cautious; asks too many clarifying questions |
| **ECHO** | Schema Architect | Proposes valid but over-engineered solutions |

Midway through the session, **Chaos Injection** introduces a second failure (Kafka consumer killed, schema column dropped) — measuring how the candidate adapts without warning.

### The fingerprint

Each session produces an **OrchestraFingerprint** — five scored dimensions:

| Dimension | What it measures |
|---|---|
| **Efficiency Ratio** | Candidate value-add over an AI-solo baseline run |
| **Trust Calibration** | Ability to audit agent output without micromanaging |
| **Correction Velocity** | Speed of detecting and correcting hallucinations |
| **Decomposition Score** | Quality of task breakdown and context in agent instructions |
| **Chaos Resilience** | Recovery speed and methodology after injected fault |

Plus: style cluster (`architect` · `executor` · `debugger` · `delegator`), interaction graph, reconstructed reasoning trace, and a narrative report generated by the Shadow Agent.

## Tech stack

| Layer | Technology | Purpose |
|---|---|---|
| Candidate sandbox | Docker + code-server | Isolated VS Code environment with broken scenario |
| Telemetry bus | Apache Kafka | Real-time event streaming (8 event types) |
| Orchestration | Apache Airflow | Scenario lifecycle, chaos injection, fingerprint assembly |
| Vector store | Qdrant | Embedding storage and benchmark similarity search |
| Graph store | Neo4j | Candidate–agent interaction graph |
| Evaluator API | FastAPI | Shadow Agent, scoring, embedding comparison |
| Multi-tenant API | FastAPI + JWT | External hiring platform integration |
| Dashboard | Next.js 14 (App Router) | Cognitive Blueprint visualization |
| Shadow Agent LLM | Claude (Anthropic SDK) | Session analysis, reasoning trace, report generation |
| Sub-agent LLM | GPT-4o | Three candidate-facing agents with distinct personas |
| Embeddings | OpenAI text-embedding-3-large | Prompt vectorization and benchmark comparison |
| Database | PostgreSQL (asyncpg) | Multi-tenant session and candidate storage |

## Setup and installation

### 1. Clone and configure environment

```bash
git clone https://github.com/octavioperez/orchid.git
cd orchid
cp .env.example .env
```

Edit `.env` with your credentials:

```bash
# Required — LLM providers
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...

# Required — JWT signing
API_SECRET_KEY=your-random-secret-min-32-chars

# Required — Admin console
ADMIN_SECRET_KEY=your-admin-secret

# Generated automatically on first run — you can leave these as-is for local dev
KAFKA_BOOTSTRAP_SERVERS=localhost:29092
QDRANT_HOST=localhost
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=orchid-local
TENANT_DB_URL=postgresql+asyncpg://orchid:orchid@localhost:5432/orchid
```

### 2. Start infrastructure

```bash
# Start all services: Kafka, Qdrant, Neo4j, Postgres, Airflow, schema registry
docker compose up -d

# Verify all services are healthy (allow ~60s on first run)
docker compose ps
```

### 3. Install Python dependencies

```bash
# Create and activate a virtual environment
python -m venv .venv
source .venv/bin/activate       # macOS/Linux
.venv\Scripts\activate          # Windows

# Install all service dependencies
pip install -r services/api/requirements.txt
pip install -r services/evaluator/requirements.txt
pip install -r services/telemetry/requirements.txt
pip install -r requirements-dev.txt
```

### 4. Install dashboard dependencies

```bash
cd services/dashboard
npm install
cd ../..
```

### 5. Initialize the database

```bash
# Schema is created automatically on API startup; or run manually:
python -c "
import asyncio
from services.api.database import init_db
asyncio.run(init_db())
"
```

## Quick start

### Start the API

```bash
uvicorn services.api.main:app --reload --port 8000
```

API available at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

### Start the dashboard

```bash
cd services/dashboard
npm run dev
```

Dashboard available at `http://localhost:3000`.

### Seed synthetic beta data

```bash
# Generate 3 tenants × 2 sessions each as JSON fixtures
python data/synthetic/seed_generator.py

# Or POST directly to a running API
python data/synthetic/seed_generator.py --api http://localhost:8000

# Custom counts
python data/synthetic/seed_generator.py --tenants 5 --sessions 3
```

### Log in to the dashboard

1. Open `http://localhost:3000` — you are redirected to `/login`
2. Generate a JWT token for a test tenant:

```bash
python -c "
from services.api.auth import create_access_token
print(create_access_token('tenant-apex-capital-beta'))
"
```

3. Paste the token into the login page → you are redirected to the Sessions list

### Use the Admin console

1. Navigate to `http://localhost:3000/admin`
2. Enter the `ADMIN_SECRET_KEY` value from your `.env`
3. Use **Generate beta fixtures** to populate the platform with synthetic tenants, candidates, sessions, and fingerprints
4. View all tenants in the registry; delete any with the **Delete** button

## API overview

All endpoints require `Authorization: Bearer <JWT>` and `X-Tenant-ID: <tenant>` headers unless noted.

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/sessions` | List sessions for the calling tenant |
| `POST` | `/sessions` | Provision a new assessment session |
| `GET` | `/sessions/{id}` | Session status and state |
| `DELETE` | `/sessions/{id}` | End a session |
| `GET` | `/sessions/{id}/fingerprint` | Assembled OrchestraFingerprint (cached 1h) |
| `POST` | `/candidates` | Register a candidate |
| `DELETE` | `/candidates/{id}` | GDPR purge — cascades to all data stores |
| `POST` | `/webhooks` | Register a webhook URL for fingerprint delivery |
| `GET` | `/scenarios` | List available assessment scenarios |
| `GET` | `/admin/tenants` | List all tenants *(admin key required)* |
| `POST` | `/admin/seed` | Generate synthetic data *(admin key required)* |
| `DELETE` | `/admin/tenants/{id}` | Purge all tenant data *(admin key required)* |
| `GET` | `/admin/sessions/{id}/cost` | Estimated LLM cost *(admin key required)* |

Full OpenAPI spec: `docs/api/openapi.yaml` · Postman collection: `docs/api/postman_collection.json`
